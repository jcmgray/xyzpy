# Project Overview

**xyzpy** is a Python library for easily generating, managing, and plotting large parameter-space datasets. It wraps functions that map input parameters to output values, runs them over combinatorial or case-based grids (optionally in parallel), and stores results as `xarray.Dataset` objects backed by netCDF/HDF5. It also provides rich plotting via matplotlib and bokeh.

- **Language:** Python (≥3.10)
- **Build system:** Hatchling + hatch-vcs (version from git tags)
- **Package manager:** [pixi](https://pixi.sh) (conda-forge based, with pixi tasks for dev workflows)
- **Key dependencies:** xarray, numpy, dask, pandas, joblib, tqdm, h5netcdf, h5py
- **Plotting backends:** matplotlib, bokeh
- **Docs:** Sphinx + myst-nb (hosted on ReadTheDocs)
- **Linter/formatter:** ruff (line-length 79, target py310, `E741` ignored)
- **Tests:** pytest + pytest-cov

# Patterns

- **xarray everywhere:** Functions produce and consume `xarray.Dataset`. Results are persisted as netCDF files via `h5netcdf`.
- **Crop/Farm workflow:** For long-running parameter sweeps, `Crop` writes individual results to disk incrementally, and `reap` combines them. `Farm` orchestrates multiple Crops.
- **CLI entry point:** `xyzpy-grow` (defined in `[project.scripts]`) calls into `xyzpy_grow:main` — a top-level module deliberately kept outside the `xyzpy` package so the entry-point import doesn't trigger `xyzpy/__init__.py` (which eagerly loads numpy/xarray) before `OMP_NUM_THREADS` and friends are set from `--num-threads`.

## Testing Patterns

- Tests live in `tests/` mirroring `xyzpy/` structure (e.g., `tests/test_gen/test_cropping.py`).
- Use `pytest` fixtures and parametrize where appropriate.
- Plotting tests are in `test_plot.py`; they may need matplotlib/bokeh installed (available in testing environments).

# Code Style

- **Formatter/linter:** ruff with `line-length = 79`, target `py310`.
- `E741` (ambiguous variable names like `l`, `O`, `I`) is intentionally ignored — the codebase uses short math-style variable names.
- Import sorting: use ruff's isort rules (`ruff check --select I`).
- Do not manually edit `xyzpy/_version.py` — it is generated by hatch-vcs from git tags.

# Commit and Pull Request Guidelines

## Before Committing

Do not stage or commit changes automatically — always leave that to the user.

Validation steps to run before the user commits:

1. Run `pixi run -e docs format` to auto-format.
2. Run `pixi run -e docs lint` and fix any issues.
3. Run `pixi run test` and ensure all tests pass.

## Commit Messages

Use the format `type: message` (lowercase), e.g.:

- `fix: correct off-by-one in combo_runner`
- `feat: add GPU resource support for grow subprocess`
- `docs: update installation instructions`
- `tests: add cropping edge case tests`

Short tags like `[skip ci]` may be appended for doc-only or badge changes.

## Pull Requests

- Describe what changed and why.
- Reference related issues if applicable.
- Ensure CI passes (tests run on Python 3.10, 3.12, and 3.14).
